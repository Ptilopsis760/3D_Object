# 3D模型自动摆放系统 - 算法端开发指南

## 项目概述

这是一个基于三维装箱问题的练手Demo项目，模拟3D打印场景下的零件空间摆放优化。项目采用双人分工模式：**算法端负责核心摆放逻辑**，UI端负责可视化渲染。本文档聚焦算法端的完整技术方案。

### 核心目标

在固定长方体空间内，自动计算多类不规则STL零件的最优摆放方案，最大化空间利用率，输出标准化的位置与旋转变换数据。

---

## 一、问题定义

### 1.1 约束条件

**硬性约束（必须满足）：**

1. **空间限制**：固定长方体封闭空间（示例尺寸：4000×2500×1500mm）
2. **输入模型**：>10类不同外形的STL三维零件模型，每类可无限复制
3. **碰撞约束**：零件之间不能发生碰撞，必须预留固定间隙（5mm）
4. **旋转自由度**：模型可沿X/Y/Z三轴任意旋转
5. **悬浮摆放**：允许空间悬浮摆放，不要求物理支撑
6. **全品类覆盖**：同批次零件中，每一类至少摆放一个

**优化目标：**

- 最大化空间利用率（不强制全局最优，获得较好近似解即可）

**拓展约束：**

- 若干零件为一批/一组
- 若空间有余量，尝试摆放第二批完整零件
- 若第三批无法完整摆放，尝试填充小零件

### 1.2 输入与输出

**输入：**

1. >10份STL模型文件（文件夹/列表形式）
2. 长方体打印腔尺寸参数（length, width, height）

**输出（算法端负责）：**

1. **结构化摆放数据**：
   - 每个零件实例的旋转矩阵（3×3或四元数）
   - 每个零件实例的位置平移向量（x, y, z）
   - 零件类型标识符（对应原始STL文件）

2. **统计指标**：
   - 空间利用率（已占用体积/总空间体积）
   - 每类零件的摆放数量
   - 总体占用体积

## 二、算法端技术方案

### 2.1 技术栈选型

| 技术组件 | 选型方案 | 用途 |
|---------|---------|------|
| STL解析库 | OpenMesh（推荐）或trimesh | 读取顶点、面片、法线等几何信息 |
| 核心算法 | 三阶段混合算法：贪心+模拟退火+局部搜索 | 三维装箱摆放计算 |
| 碰撞检测 | AABB包围盒 + 精细检测（可选OBB） | 快速剔除 + 精确判定 |
| 数据结构 | 八叉树/空间网格 | 加速空间查询 |
| 开发语言 | Java（主） + Python工具脚本（辅助） | 与UI端集成 |

**算法选型说明**：

基于2026年MDPI研究发现："解码器优化比复杂元启发式更重要"，本项目采用**混合优化策略**：
- **阶段1（贪心初始化）**：快速生成高质量初始解（1-2秒）
- **阶段2（模拟退火优化）**：全局搜索，跳出局部最优（8-12秒）
- **阶段3（局部搜索精修）**：邻域搜索，精细调优（2-3秒）

预期性能：空间利用率78-85%，总计算时间12-17秒，性价比最优。

### 2.2 核心模块设计

#### 模块1：STL模型解析与预处理

**功能职责：**

- 批量读取STL文件（支持ASCII和Binary格式）
- 提取顶点坐标、三角面片、法向量
- 计算模型中心点、体积、表面积
- 生成最小包围盒（Bounding Box）

**关键算法：**

1. **AABB包围盒计算**（Axis-Aligned Bounding Box）
   ```
   对于模型M的所有顶点V：
     min_x = min(V[i].x), max_x = max(V[i].x)
     min_y = min(V[i].y), max_y = max(V[i].y)
     min_z = min(V[i].z), max_z = max(V[i].z)
   包围盒尺寸 = (max_x - min_x, max_y - min_y, max_z - min_z)
   ```

2. **旋转后包围盒更新**
   - 应用旋转矩阵R到所有顶点
   - 重新计算旋转后的AABB
   - 用于后续碰撞检测

**输出数据结构：**

```java
class ModelInfo {
    String fileName;           // STL文件名
    List<Vector3D> vertices;   // 顶点列表
    List<Triangle> faces;      // 三角面片
    BoundingBox aabb;          // 轴对齐包围盒
    float volume;              // 模型体积
    Vector3D centerOfMass;     // 质心/几何中心
}
```

**实现难点与应对：**

- **难点1**：不规则模型顶点数量巨大（数万级），直接计算碰撞检测复杂度O(n²)不可接受
  - **应对**：用AABB包围盒简化模型，先做粗检测，碰撞候选再做精细检测
  
- **难点2**：STL文件格式多样（ASCII/Binary、不同单位、坐标系差异）
  - **应对**：统一预处理为标准单位（mm），中心化坐标系，归一化法向量

#### 模块2：三维空间管理与碰撞检测

**功能职责：**

- 维护打印腔空间状态（已占用/空闲区域）
- 检测零件与零件、零件与边界的碰撞
- 检测间隙约束（5mm最小距离）
- 快速查询可摆放位置

**关键算法：**

1. **八叉树空间划分**（加速空间查询）
   ```
   - 递归将空间分为8个子立方体
   - 叶节点存储已摆放零件引用
   - 查询候选碰撞对象时仅检查相邻区域
   ```

2. **两阶段碰撞检测**
   ```
   阶段1：AABB包围盒快速剔除
     if (box1.max_x < box2.min_x || box1.min_x > box2.max_x) return false;
     // Y轴、Z轴同理
     if (距离 < 5mm) return true; // 违反间隙约束
   
   阶段2：精细检测（仅对包围盒相交的候选对）
     使用SAT分离轴定理或GJK算法
   ```

3. **间隙约束扩展**
   - 将每个零件的AABB外扩5mm作为"禁入区"
   - 任何新零件不得与禁入区相交

**输出数据结构：**

```java
class SpaceManager {
    Octree spatialIndex;              // 八叉树索引
    List<PlacedModel> placedModels;   // 已摆放零件列表
    BoundingBox workspace;            // 工作空间边界
    
    boolean checkCollision(PlacedModel newModel);
    List<Vector3D> findCandidatePositions();
}

class PlacedModel {
    ModelInfo model;            // 模型信息
    Matrix3x3 rotationMatrix;   // 旋转矩阵
    Vector3D position;          // 摆放位置（包围盒左下角）
    BoundingBox transformedAABB;// 旋转平移后的包围盒
}
```

**实现难点与应对：**

- **难点3**：零件三轴旋转后包围盒尺寸动态变化，碰撞检测复杂
  - **应对**：
    1. 离散化旋转角度（如每15°一个档位，减少组合爆炸）
    2. 预计算常用旋转角度下的包围盒（空间换时间）
    3. 优先尝试轴对齐摆放（0°/90°/180°/270°），降低复杂度

- **难点4**：精细碰撞检测计算量大
  - **应对**：仅对AABB相交的候选对进行精细检测，大部分情况通过包围盒快速剔除

#### 模块3：三阶段混合摆放算法

**核心思想：**

采用**贪心初始化 + 模拟退火优化 + 局部搜索精修**的混合策略，兼顾计算速度与解的质量。

---

### 阶段1：贪心初始化（快速生成初始解）

**目标**：1-2秒内生成可行解，空间利用率≥65%

**算法流程**：

```
function GreedyInitialization(models, workspace):
    solution = new PlacementSolution()
    spaceManager = new SpaceManager(workspace)
    
    // 按体积从大到小排序（大件优先策略）
    sortedModels = sortByVolume(models, descending=True)
    
    // 第一批：保证每类至少1个（硬约束）
    for model in sortedModels:
        bestPose = findBestPoseGreedy(model, spaceManager)
        if bestPose != null:
            place(model, bestPose, spaceManager)
            solution.add(model, bestPose)
    
    // 贪心扩展：继续摆放直到空间利用率达80%
    while spaceManager.utilization < 0.80:
        for model in sortedModels:
            bestPose = findBestPoseGreedy(model, spaceManager)
            if bestPose != null:
                place(model, bestPose, spaceManager)
                solution.add(model, bestPose)
            else:
                break  // 无法再摆放该类零件
    
    return solution
```

**位置选择策略（DBLF解码器）**：

```
function findBestPoseGreedy(model, spaceManager):
    bestScore = -infinity
    bestPose = null
    
    // 离散化旋转角度（减少搜索空间）
    rotations = [0°, 90°, 180°, 270°] × [0°, 90°, 180°, 270°] × [0°, 90°]
    
    for rotation in rotations:
        rotatedModel = applyRotation(model, rotation)
        
        // 候选位置：底角、贴墙、堆叠
        candidates = generateCandidatePositions(spaceManager)
        
        for position in candidates:
            if not spaceManager.checkCollision(rotatedModel, position):
                score = evaluatePosition(rotatedModel, position, spaceManager)
                if score > bestScore:
                    bestScore = score
                    bestPose = (position, rotation)
    
    return bestPose
```

**评分函数**：

```
score(position, rotation) = 0.5 * utilization_rate 
                          + 0.3 * compactness_score
                          + 0.2 * stability_score
                          - 0.1 * gap_penalty

其中：
- utilization_rate: 局部空间利用率（周围8×8×8体素块的占用率）
- compactness_score: 紧凑度（与已摆放零件最近距离的倒数）
- stability_score: 稳定性（底部支撑面积/总底面积）
- gap_penalty: 间隙惩罚（产生的<50mm³小缝隙数量）
```

### 阶段2：模拟退火优化（全局搜索）

**目标**：8-12秒内跳出局部最优，提升利用率5-10%

**算法原理**：

模拟退火通过概率性接受劣解，避免陷入局部最优。温度高时接受劣解概率大，温度降低后逐渐收敛。

**算法流程**：

```
function SimulatedAnnealing(initialSolution, workspace):
    currentSolution = initialSolution
    bestSolution = initialSolution
    temperature = 100.0  // 初始温度
    coolingRate = 0.95   // 降温速率
    
    while temperature > 1.0:
        // 生成邻域解
        neighborSolution = generateNeighbor(currentSolution)
        
        // 计算能量差（利用率差）
        deltaE = neighborSolution.utilization - currentSolution.utilization
        
        // Metropolis准则：决定是否接受新解
        if deltaE > 0:
            // 新解更优，直接接受
            currentSolution = neighborSolution
            if currentSolution.utilization > bestSolution.utilization:
                bestSolution = currentSolution
        else:
            // 新解较差，以一定概率接受
            acceptProb = exp(deltaE / temperature)
            if random() < acceptProb:
                currentSolution = neighborSolution
        
        // 降温
        temperature *= coolingRate
    
    return bestSolution
```

**邻域操作（生成新解）**：

```
function generateNeighbor(solution):
    operation = randomChoice([SWAP, ROTATE, REPOSITION, REMOVE_AND_INSERT])
    
    switch operation:
        case SWAP:
            // 交换两个零件的位置
            idx1, idx2 = randomSelectTwo(solution.models)
            swap(solution.models[idx1], solution.models[idx2])
        
        case ROTATE:
            // 随机旋转一个零件
            idx = randomSelect(solution.models)
            newRotation = randomRotation()
            solution.models[idx].rotation = newRotation
        
        case REPOSITION:
            // 移动一个零件到新位置
            idx = randomSelect(solution.models)
            newPosition = findNearbyPosition(solution.models[idx])
            solution.models[idx].position = newPosition
        
        case REMOVE_AND_INSERT:
            // 移除一个零件，重新用贪心插入
            idx = randomSelect(solution.models)
            model = solution.models.remove(idx)
            newPose = findBestPoseGreedy(model, solution.spaceManager)
            solution.add(model, newPose)
    
    return solution
```

**参数调优**：

- **初始温度T₀**：100（允许前期接受较差解）
- **降温速率α**：0.95（每次迭代温度降为原来的95%）
- **终止温度Tₑ**：1.0（温度过低时停止）
- **每温度迭代次数**：50次

### 阶段3：局部搜索精修（邻域优化）

**目标**：2-3秒内精细调优，提升利用率2-3%

**算法流程**：

```
function LocalSearch(solution, workspace):
    improved = True
    iterCount = 0
    maxIter = 100
    
    while improved and iterCount < maxIter:
        improved = False
        iterCount++
        
        // 策略1：位置微调（每个零件尝试周围26个邻居位置）
        for model in solution.models:
            for offset in [(-δ,0,0), (+δ,0,0), (0,-δ,0), ...]:  // δ=10mm
                newPosition = model.position + offset
                if tryMove(model, newPosition, solution.spaceManager):
                    if solution.utilization > previousUtilization:
                        improved = True
        
        // 策略2：旋转微调（尝试±5°、±10°的小角度旋转）
        for model in solution.models:
            for angleOffset in [-10°, -5°, +5°, +10°]:
                newRotation = model.rotation + angleOffset
                if tryRotate(model, newRotation, solution.spaceManager):
                    if solution.utilization > previousUtilization:
                        improved = True
        
        // 策略3：间隙填充（尝试在大零件间插入小零件）
        smallModels = getSmallestModels(models, count=3)
        for gap in detectGaps(solution.spaceManager):
            for smallModel in smallModels:
                if canFit(smallModel, gap):
                    insert(smallModel, gap, solution)
                    improved = True
    
    return solution
```

**关键技术**：

1. **快速增量更新**：移动/旋转零件后，仅重新计算受影响区域的碰撞检测
2. **Tabu禁忌表**：避免重复尝试已失败的移动操作（记录最近50次失败操作）
3. **早停机制**：连续10次迭代无改进则提前终止

### 实现难点与应对

**难点5**：模拟退火温度参数难以调优
- **应对**：采用自适应降温策略，根据接受率动态调整温度下降速度
  ```
  if acceptRate > 0.8: coolingRate = 0.90  // 接受率高，降温快
  if acceptRate < 0.2: coolingRate = 0.98  // 接受率低，降温慢
  ```

**难点6**：邻域操作可能产生不可行解（碰撞）
- **应对**：
  1. 每次邻域操作后立即检查可行性，不可行则回退
  2. 设计"修复"函数：碰撞时微调位置使其可行
  3. 限制邻域操作范围（移动距离<50mm，旋转角度<15°）

**难点7**：局部搜索陷入无效循环
- **应对**：
  1. 使用Tabu禁忌表，避免重复尝试失败操作
  2. 连续10次迭代无改进则early stop
  3. 限制最大迭代次数（100次）

- ⚠️ **风险1**：模拟退火陷入无限循环或收敛过慢

    2. 监控接受率，<5%时提前终止
    3. 使用自适应降温避免过早/过晚收敛

- ⚠️ **风险2**：邻域操作频繁产生不可行解，影响效率
  - **应对**：
    1. 限制邻域操作范围（移动<50mm，旋转<15°）
    2. 实现"修复"函数，微调使碰撞解可行
    3. 统计各操作成功率，动态调整操作选择概率

- ⚠️ **风险3**：最终利用率无法达到78%
  - **应对**：
    1. 调优评分函数权重系数
    2. 增加模拟退火迭代次数（100→200）
    3. 引入多次运行取最优（运行3次选最佳）
